Log10x Edge Reporter has been deployed as a DaemonSet.

  Release: {{ .Release.Name }}
  Namespace: {{ .Release.Namespace }}

Architecture:
  [fluent-bit] ──forward──▶ [10x reporter]
    (tail)       (unix sock)   (analyze & report)

The reporter runs in parallel to your existing log forwarder.
Fluent Bit tails container logs, forwards them via Unix socket to the
Log10x sidecar for analysis and metrics reporting. Logs are NOT forwarded
to any external destination.

{{- if and .Values.licenseSecret.create .Values.log10xLicenseJwt }}

NOTE: A license JWT was passed inline via 'log10xLicenseJwt'. The chart materialized it into a Kubernetes Secret, but the raw value is still visible in your release values (helm get values {{ .Release.Name }} -n {{ .Release.Namespace }}).
For production, prefer pre-creating a Secret out of band and referencing it:

  licenseSecret:
    create: false
    existingSecret: <your-secret-name>
    secretKey: license-jwt
{{- end }}

The engine container has no liveness probe. The engine exposes no health
surface to probe, so the chart does not ship one that cannot fail. If the
engine exits, the container exits with it and the kubelet restarts the pod.

To check the status:
  kubectl get daemonset {{ include "log10x-reporter.fullname" . }} -n {{ .Release.Namespace }}

To view Fluent Bit logs:
  kubectl logs -l app.kubernetes.io/name={{ include "log10x-reporter.name" . }} -c fluent-bit -n {{ .Release.Namespace }}

To view Log10x logs:
  kubectl logs -l app.kubernetes.io/name={{ include "log10x-reporter.name" . }} -c tenx -n {{ .Release.Namespace }}
